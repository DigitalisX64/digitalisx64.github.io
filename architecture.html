1. End-to-End Pipeline

When you launch an arm64-v8a APK on a Digitalis emulator, Android's NativeBridge hands control to libberberis_arm64.so. From that point every ARM64 instruction inside the app and its libraries flows through the translator until it reaches the host x86_64 CPU or GPU. Hover any node for details.

2. Dual Dispatch — JIT and Interpreter

Every ARM64 instruction is handled by one of two execution engines. The JIT covers the fast path; the interpreter is the safety net.

Lite Translator (JIT)

Translates contiguous ARM64 regions to native x86_64 machine code. Output is stored in a per-process translation cache and reused on subsequent entries. Handles integer ops, branches, loads/stores, system instructions, and most NEON/SIMD.

~98% of instructions

Interpreter (Fallback)

Per-instruction execution for things the JIT punts on: syscalls, complex SIMD (pairwise, widening, permute, across-lanes, CRC32), scalar conversions, and any decoder edge case. A region terminates JIT compilation when it hits an interpreter-only opcode.

fallback path

When the dispatcher reaches a guest PC for the first time, the decoder peeks at the instruction. If the JIT can handle it, a region is compiled. If not, a special kInterpreted marker is installed at that PC so the next entry routes straight to the interpreter — avoiding infinite recompile loops.

3. Worked Example — One Instruction at a Time

Click a tab to walk through the actual ARM64 → x86_64 transformation the JIT emits. The x86_64 listings assume RBP points at ThreadState and that the source guest registers are spilled (worst case — pinned registers produce shorter code).

Arith Logic Move/Addr Memory Atomic Branch System FP SIMD

ADD X0, X1, X2 — add two registers

ARM64 source

; ARM64 (4 bytes, little-endian)
ADD X0, X1, X2     ; 0x8b020020

31-bit encoding: sf=1 (64-bit) op=0 (add) S=0 (no flags) shift=00 Rm=X2 imm6=0 Rn=X1 Rd=X0.

JIT emits (x86_64)

mov  rax, [rbp + x1_off]  ; load guest X1
add  rax, [rbp + x2_off]  ; add guest X2
mov  [rbp + x0_off], rax  ; store back as X0

Three host ops, no flag emission (no ADDS). If X1 or X2 are already pinned to an x86 register the loads collapse away.

MOVZ X0, #0x1234 — zero-extend immediate

ARM64 source

; ARM64
MOVZ X0, #0x1234   ; 0xd2824680

MOVZ writes a 16-bit immediate into a 64-bit register, zeroing the other bits. ARM64 has no single “load any 64-bit immediate” instruction; bigger constants compose MOVZ + up to three MOVKs.

JIT emits (x86_64)

mov  qword [rbp + x0_off], 0x1234

Single store; x86 can move 32-bit immediates directly to memory and zero-extend.

LDR X0, [X1, #16] — load with offset

ARM64 source

; ARM64
LDR X0, [X1, #16]  ; 0xf9400820

Loads 8 bytes from the address X1 + 16 into X0. ARM64 unsigned-offset form, imm12=2 scaled by 8.

JIT emits (x86_64)

mov  rax, [rbp + x1_off]  ; guest pointer
mov  rax, [rax + 16]      ; guest load (host SIGSEGV  
                          ; handler forwards to guest)
mov  [rbp + x0_off], rax  ; store result as X0

The interpreter version wraps this in FaultyLoad so the host SIGSEGV handler can deliver a synthetic guest signal — a raw memcpy would crash the host process.

CBZ X0, .Ltarget — compare and branch if zero

ARM64 source

; ARM64
CBZ X0, .Ltarget   ; 0xb4000020

Branches to .Ltarget if X0 == 0. Does not touch NZCV.

JIT emits (x86_64)

cmp  qword [rbp + x0_off], 0
je   L_target_host        ; emit-time-known
                          ; fall through =  
                          ; next guest instr

Forward branches inside the region are resolved to host labels. Out-of-region branches end the region with an exit stub that returns to the dispatcher with the new guest PC.

BL <symbol> — branch with link (call)

ARM64 source

; ARM64
BL  foo            ; 0x94000000
                   ; + signed imm26<<2 offset

Writes the return address (PC + 4) into X30 (LR), then jumps to the call target.

JIT emits (x86_64)

mov  qword [rbp + x30_off], ; LR ←
     <next_guest_pc>      ; PC + 4
mov  rax, <callee_pc>     ; guest PC of foo
ret                       ; exit to dispatcher

BL always terminates the JIT region. The dispatcher looks up <callee_pc> in the translation cache and enters the callee.

ADDS X0, X1, X2 — add and set NZCV

ARM64 source

; ARM64
ADDS X0, X1, X2    ; 0xab020020

Same as ADD but additionally updates the NZCV condition flags. The next conditional instruction (B.cc, CSEL, CSET…) will read those flags.

JIT emits (x86_64)

mov   rax, [rbp + x1_off]
add   rax, [rbp + x2_off] ; sets RFLAGS
mov   [rbp + x0_off], rax
lahf                      ; SF/ZF/CF -> AH
seto  al                  ; OF -> AL
and   ax, 0xc101          ; isolate N,Z,C,V
mov   [rbp + nzcv_off], ax

The four-instruction flag-capture tail is the same pattern documented in Section 7. PUSH/POP — not SUB RSP — are used for any spills between add and lahf because SUB would clobber RFLAGS.

ADRP + ADD — PC-relative address (PIC pattern)

ARM64 source

; ARM64 — produce &foo
ADRP X0, foo            ; 0x90000000+imm
ADD  X0, X0, :lo12:foo  ; 0x91000000+imm

ARM64 has no movabs-equivalent. PIC code addresses globals via this two-instruction pair: ADRP loads the page (bits 63:12), ADD adds the low 12 bits.

JIT emits (x86_64)

; emit-time constant fold
; both halves of the address  
; are known when the region  
; is compiled
mov  rax, <foo_addr>
mov  [rbp + x0_off], rax

The lite translator recognizes the ADRP/ADD pair and collapses it to a single immediate load — one of the JIT's most-frequent win patterns since every function call to a global goes through it.

STP X29, X30, [SP, #-16]! — function prologue

ARM64 source

; ARM64
STP X29, X30, [SP, #-16]!  ; 0xa9bf7bfd

Pushes the saved frame pointer (X29) and return address (X30) onto the guest stack in one instruction, with pre-index writeback (SP is updated before the store). The single most common function-prologue opcode.

JIT emits (x86_64)

mov  rax, [rbp + sp_off]
sub  rax, 16              ; pre-decrement SP
mov  rcx, [rbp + x29_off]
mov  [rax],     rcx       ; store X29
mov  rcx, [rbp + x30_off]
mov  [rax + 8], rcx       ; store X30
mov  [rbp + sp_off], rax  ; write SP back

Pair load/store with pre/post-index turns into one address computation, two memory ops, and a single SP write-back. Post-index (no !) instead stores first, then updates.

B.EQ .Ltarget — conditional branch on Z flag

ARM64 source

; ARM64
B.EQ .Ltarget      ; 0x54000000+imm

14 ARM64 condition codes (EQ, NE, CS/HS, CC/LO, MI, PL, VS, VC, HI, LS, GE, LT, GT, LE) all decode to a Boolean function of NZCV. EQ means “Z == 1”.

JIT emits (x86_64)

movzx eax, word ptr      ; load packed NZCV
      [rbp + nzcv_off]
test  ax, 0x4000          ; Z bit
jnz   L_target_host       ; branch if Z=1

Each cc maps to a different mask + test + Jcc trio. Worth noting: the JIT picks jnz here rather than je because Z=1 in NZCV means the masked bit is non-zero in the captured word.

CSEL X0, X1, X2, EQ — conditional select

ARM64 source

; ARM64
CSEL X0, X1, X2, EQ  ; 0x9a820020

Branchless “X0 = (Z == 1) ? X1 : X2”. Pair instructions CSINC, CSINV, CSNEG add a +1/~/-1 to the “else” operand. Critical for compiler-generated branchless code paths.

JIT emits (x86_64)

movzx eax, word ptr [rbp + nzcv_off]
test  ax, 0x4000           ; Z bit
mov   rax, [rbp + x2_off]  ; else value
mov   rdx, [rbp + x1_off]  ; then value
cmovnz rax, rdx            ; pick on Z=1
mov   [rbp + x0_off], rax

x86's cmovcc family maps cleanly onto ARM CSEL. The allocator must temporarily reserve RDX for the “then” value here — one of the cases where RDX leaves the general pool.

FMOV X0, D0 — cross-bank register move (the one with the bug)

ARM64 source

; ARM64 — copy bits of FP D0
; (lower 64 of V0) into GP X0
FMOV X0, D0        ; 0x9e660000

Bridges the FP/SIMD register file (V0–V31) and the GP register file. Doesn't actually convert anything — just reinterprets the bytes. ARM64 has FMOV X,D and FMOV D,X as a pair.

JIT emits (x86_64)

; if V0 is pinned to xmm10, the
; allocator must flush xmm10 to
; [rbp + v0_off] FIRST — the bug
; was skipping that flush
movq rax, qword ptr [rbp + v0_off]
mov  [rbp + x0_off], rax

The FMOV cross-bank case had a real cache-coherency bug (fixed in commit 23f12f72): if the source FP register was sitting in a host XMM and the destination GP register wasn't pinned, the JIT could read a stale ThreadState slot. Cross-bank moves must always go through memory.

MUL X0, X1, X2 — multiply (the RDX dance)

ARM64 source

; ARM64 — alias for
; MADD X0, X1, X2, XZR
MUL X0, X1, X2     ; 0x9b027c20

64x64 -> 64 multiply. The upper 64 bits of the product are dropped. ARM also has UMULH / SMULH for the high half.

JIT emits (x86_64)

push rdx                  ; preserve any guest
                          ; reg pinned to rdx
mov  rax, [rbp + x1_off]
mul  qword [rbp + x2_off] ; RDX:RAX = RAX * mem
mov  [rbp + x0_off], rax
pop  rdx                  ; restore

x86 mul clobbers both RAX and RDX. The allocator keeps RDX in the GP pool but must push/pop it across MUL/DIV. PUSH is used (not SUB RSP) so RFLAGS isn't disturbed — same reason as the NZCV-capture sequence.

LSL X0, X1, X2 — variable shift (the RCX dance)

ARM64 source

; ARM64 (alias of LSLV)
LSL X0, X1, X2     ; 0x9ac22020

Variable shift — the amount comes from a register, not an immediate. ARM masks the shift amount mod 64; x86 already does the same on 64-bit operands.

JIT emits (x86_64)

push rcx                  ; preserve guest reg
                          ; in rcx, if any
mov  rcx, [rbp + x2_off]
mov  rax, [rbp + x1_off]
shl  rax, cl              ; variable shift uses CL
mov  [rbp + x0_off], rax
pop  rcx

x86 variable shifts (shl/shr/sar with a register operand) read from CL only. Same pattern as MUL: RCX is part of the GP pool but must be saved across any variable-shift sequence.

LDP X29, X30, [SP], #16 — load pair (function epilogue)

ARM64 source

; ARM64 — post-index writeback
LDP X29, X30, [SP], #16  ; 0xa8c17bfd

Pops X29 and X30 off the guest stack and post-increments SP by 16. The mirror image of STP X29, X30, [SP, #-16]!. Every non-leaf function pairs these two.

JIT emits (x86_64)

mov  rax, [rbp + sp_off]    ; guest SP
mov  rcx, [rax]             ; first 8 bytes
mov  rdx, [rax + 8]         ; next 8 bytes
mov  [rbp + x29_off], rcx   ; store X29
mov  [rbp + x30_off], rdx   ; store X30 (LR)
add  rax, 16                ; post-increment
mov  [rbp + sp_off], rax

Two loads + one address adjustment + one SP store. Note the post-index here vs pre-index in STP: the LDP form reads from the old SP, then bumps. Often immediately followed by a RET.

STLR W0, [X1] — store-release (decoder bug history)

ARM64 source

; ARM64 — release store, 32-bit
STLR W0, [X1]      ; 0x889ffc20

Store with release semantics: all preceding loads/stores must complete before this store becomes visible. The acquire/release counterparts (LDAR, STLR) are how ARM64 implements std::atomic for ordinary data.

JIT emits (x86_64)

mov  rax, [rbp + x1_off]  ; guest pointer
mov  ecx, [rbp + x0_off]  ; W0 (low 32 of X0)
mov  [rax], ecx           ; plain store -- x86
                          ; TSO gives release
                          ; semantics for free

x86's memory model (TSO) already provides release ordering for normal stores, so the JIT can emit a plain mov. The real-world bug here was in the decoder, not the codegen: STLR shares encoding prefix bits with other load/store-exclusive forms, and dispatch order had to be fixed so STLR didn't get routed to a sibling handler (commit f5876fad).

CAS W0, W1, [X2] — atomic compare-and-swap

ARM64 source

; if [X2] == W0: [X2] = W1
; W0 := old [X2] in any case
CAS W0, W1, [X2]   ; 0x88a07c40

ARMv8.1 atomic CAS. Returns the original value of [X2] in W0 — success is detected by the caller comparing it to the expected value.

JIT emits (x86_64)

mov  rax, [rbp + x2_off]   ; guest pointer
mov  eax, [rbp + x0_off]   ; expected -> EAX
mov  edx, [rbp + x1_off]   ; new value -> EDX
lock cmpxchg [rax], edx    ; atomic CAS
mov  [rbp + x0_off], rax   ; old value -> W0
                           ; (zero-extends upper 32)

CAS maps almost one-to-one onto x86 lock cmpxchg. The historical danger was in the decoder: CAS, SWP, and LDADD share encoding prefixes and can silently route to each other — SWP-as-CAS would produce wrong results without crashing until a memory boundary surfaced the bug.

RET — return through LR (X30)

ARM64 source

; ARM64 — alias for RET X30
RET                ; 0xd65f03c0

Indirect branch through X30 (LR). Conceptually pops nothing — the return address has been in LR since the BL that called this function. Marks region exit.

JIT emits (x86_64)

mov  rax, [rbp + x30_off]  ; new guest PC = LR
ret                         ; exit to dispatcher

Two instructions and the region is done. The dispatcher looks up rax as the next guest PC. Return-address prediction in the host CPU helps: the host ret here is paired with the host call that entered the dispatcher.

BR X16 — indirect branch (jump tables, function pointers)

ARM64 source

; ARM64
BR  X16            ; 0xd61f0200

Jump to the address in X16. PLT thunks and switch-statement jump tables use BR. BLR Xn is the call-with-link variant (writes X30 = PC+4 first).

JIT emits (x86_64)

mov  rax, [rbp + x16_off]  ; new guest PC
ret                         ; exit to dispatcher

Same shape as RET, but the target is arbitrary. The dispatcher cache hits if the target has already been translated. Unlike direct branches, the JIT cannot link the next region inline — the target isn't known until runtime.

SUB X0, X1, X2 — subtract

ARM64 source

SUB X0, X1, X2    ; 0xcb020020

Same shape as ADD but with subtraction. SUBS sets NZCV. ARM's NEG Xd, Xm is SUB Xd, XZR, Xm; NEGS is SUBS XZR.

JIT emits (x86_64)

mov  rax, [rbp + x1_off]
sub  rax, [rbp + x2_off]
mov  [rbp + x0_off], rax

x86 carry flag semantics for subtraction differ from ARM's (ARM C = NOT borrow), so SUBS gets an extra cmc in the flag-capture tail.

CMP X0, X1 — compare (alias for SUBS XZR, X0, X1)

ARM64 source

CMP X0, X1        ; 0xeb01001f

Sets NZCV based on X0 - X1; discards the result. The compiler emits CMP before every conditional that compares two values.

JIT emits (x86_64)

mov  rax, [rbp + x0_off]
cmp  rax, [rbp + x1_off]  ; sets RFLAGS
lahf
seto al
and  ax, 0xc101
mov  [rbp + nzcv_off], ax
; (with cmc for borrow->C)

No result store — CMP exists purely to set NZCV. Often paired with the next B.cc or CSEL within the same region.

UDIV X0, X1, X2 — unsigned divide (RDX:RAX dance)

ARM64 source

UDIV X0, X1, X2   ; 0x9ac20820

64-bit unsigned divide. ARM defines divide-by-zero to return 0 (no trap), unlike x86 which raises #DE.

JIT emits (x86_64)

push rdx
mov  rcx, [rbp + x2_off]
test rcx, rcx             ; divide-by-zero
jz   L_zero               ; -> result = 0
xor  edx, edx             ; clear RDX
mov  rax, [rbp + x1_off]
div  rcx                  ; RAX = RDX:RAX/rcx
mov  [rbp + x0_off], rax
jmp  L_done
L_zero: mov qword [rbp + x0_off], 0
L_done: pop rdx

x86 traps on divide-by-zero, so the JIT inserts an explicit zero check to preserve ARM semantics. RDX must be cleared and then saved/restored around the host div.

AND X0, X1, X2 — bitwise and

ARM64 source

AND X0, X1, X2    ; 0x8a020020

Trivial bitwise AND. ANDS sets NZCV (only N and Z meaningfully — C, V cleared). BIC is AND with the second operand inverted.

JIT emits (x86_64)

mov  rax, [rbp + x1_off]
and  rax, [rbp + x2_off]
mov  [rbp + x0_off], rax

ORR X0, X1, X2 — bitwise or

ARM64 source

ORR X0, X1, X2    ; 0xaa020020

Bitwise OR. MOV Xd, Xm is the alias ORR Xd, XZR, Xm. ORN is OR with second operand inverted.

JIT emits (x86_64)

mov  rax, [rbp + x1_off]
or   rax, [rbp + x2_off]
mov  [rbp + x0_off], rax

EOR X0, X1, X2 — bitwise exclusive-or

ARM64 source

EOR X0, X1, X2    ; 0xca020020

Bitwise XOR. EOR Xd, Xn, Xn is a common idiom to zero a register without a load; the JIT recognizes it.

JIT emits (x86_64)

mov  rax, [rbp + x1_off]
xor  rax, [rbp + x2_off]
mov  [rbp + x0_off], rax

TST X0, #mask — test bits (alias for ANDS XZR, ...)

ARM64 source

TST X0, #0xff     ; 0xf2401c1f

Computes X0 & mask and sets NZCV (mostly Z). The result is discarded. Used for bit testing before a B.cc.

JIT emits (x86_64)

test qword [rbp + x0_off], 0xff
lahf
seto al
and  ax, 0xc101
mov  [rbp + nzcv_off], ax

x86 test sets Z and clears C/V/O — matches ANDS exactly.

CLZ X0, X1 — count leading zeros

ARM64 source

CLZ X0, X1        ; 0xdac01020

Counts leading zero bits in X1; returns 64 if all zero. Common in floating-point unpacking and bit-scan algorithms.

JIT emits (x86_64)

mov  rax, [rbp + x1_off]
lzcnt rax, rax            ; BMI1 instruction
mov  [rbp + x0_off], rax

x86 lzcnt is from BMI1 and matches ARM CLZ exactly (including the all-zeros case). Older CPUs would need bsr + branch for the zero case.

MOVK X0, #0xbeef, LSL #16 — move with keep

ARM64 source

MOVK X0, #0xbeef, LSL #16  ; 0xf2a7ddc0

Overwrites bits [31:16] of X0 with 0xbeef; keeps every other bit. Chained MOVZ + MOVK + MOVK + MOVK builds an arbitrary 64-bit immediate.

JIT emits (x86_64)

mov  rax, [rbp + x0_off]
and  rax, ~0xffff0000     ; clear bits 31:16
or   rax, 0xbeef0000      ; set new bits
mov  [rbp + x0_off], rax

No single x86 op writes 16 bits at a specific shift; mask + OR is the canonical sequence.

SXTW X0, W1 — sign-extend word to doubleword

ARM64 source

SXTW X0, W1       ; 0x93407c20
                  ; alias of SBFM

Sign-extends the low 32 bits of X1 into the full 64 bits of X0. UXTW (or just MOV) zero-extends.

JIT emits (x86_64)

movsxd rax, dword [rbp + x1_off]
mov  [rbp + x0_off], rax

x86 movsxd reads 32 bits and sign-extends to 64 in one op. UXTW becomes just mov eax, dword ... (zero-extends naturally).

LDRB W0, [X1] — load byte, zero-extend

ARM64 source

LDRB W0, [X1]     ; 0x39400020

Loads 1 byte from [X1] into W0; upper 56 bits of X0 are zeroed. LDRH is the halfword variant; LDRSB/LDRSH/LDRSW sign-extend.

JIT emits (x86_64)

mov   rax, [rbp + x1_off]
movzx eax, byte [rax]     ; zero-ext 8 -> 32
                          ; (and 32 -> 64 auto)
mov   [rbp + x0_off], rax

x86 32-bit writes zero-extend to 64 for free, matching ARM's behavior of zeroing the upper half on W-register writes.

STR X0, [X1, #16] — store with offset

ARM64 source

STR X0, [X1, #16] ; 0xf9000820

Stores 8 bytes from X0 to [X1 + 16]. STRB/STRH/STR(W) for narrower stores.

JIT emits (x86_64)

mov  rax, [rbp + x1_off]
mov  rcx, [rbp + x0_off]
mov  [rax + 16], rcx

LDAR W0, [X1] — load-acquire

ARM64 source

LDAR W0, [X1]     ; 0x88dffc20

Load with acquire semantics: no subsequent loads/stores can be reordered before this load. Paired with STLR to implement std::atomic on data-only types.

JIT emits (x86_64)

mov  rax, [rbp + x1_off]
mov  ecx, [rax]           ; plain load -- x86
                          ; TSO gives acquire
mov  [rbp + x0_off], rcx

Just like STLR, plain x86 loads already have acquire ordering under TSO. No fence needed for ordinary data.

LDADD W0, W1, [X2] — atomic load-add (the mis-routing case)

ARM64 source

LDADD W0, W1, [X2]   ; 0xb8200040

Atomically: old = *X2; *X2 = old + W0; W1 = old. Implements std::atomic<int>::fetch_add. SWP, LDSET, LDEOR, LDCLR, LDSMAX, LDSMIN, LDUMAX, LDUMIN are the family siblings.

JIT emits (x86_64)

mov  rax, [rbp + x2_off]
mov  ecx, [rbp + x0_off]  ; addend
lock xadd [rax], ecx      ; atomic fetch-add
mov  [rbp + x1_off], rcx  ; old value -> W1

x86 lock xadd maps directly. The historical decoder bug: LDADD, SWP, and the LDcc family share an encoding prefix — getting the dispatch order wrong silently routes them to each other (CLAUDE.md flags this as a top pitfall).

CBNZ X0, .Ltarget — branch if non-zero

ARM64 source

CBNZ X0, .Ltarget ; 0xb5000020

Mirror of CBZ — branches when X0 != 0. Does not touch NZCV.

JIT emits (x86_64)

cmp  qword [rbp + x0_off], 0
jne  L_target_host

TBZ X0, #5, .Lskip — test bit and branch if zero

ARM64 source

TBZ X0, #5, .Lskip   ; 0x36280020

Branches if bit 5 of X0 is zero. The encoded bit position is 6 bits (0–63), so one TBZ covers any single bit. TBNZ is the complement.

JIT emits (x86_64)

bt   qword [rbp + x0_off], 5
jnc  L_skip_host          ; CF=bit5; jnc=bit==0

x86 bt copies the named bit into CF; jnc takes the branch when CF=0.

CSET X0, EQ — set 1 if condition holds, else 0

ARM64 source

CSET X0, EQ       ; 0x9a9f17e0
                  ; alias of CSINC XZR, XZR, !cond

Materializes a Boolean from a condition flag — the typical idiom for bool b = (a == b).

JIT emits (x86_64)

movzx eax, word [rbp + nzcv_off]
test  ax, 0x4000          ; Z bit
setnz al                  ; 0 or 1
movzx rax, al
mov   [rbp + x0_off], rax

x86's setcc family writes one byte (0 or 1); a movzx widens for the 64-bit guest register.

BLR X3 — branch with link to register

ARM64 source

BLR X3            ; 0xd63f0060

Indirect call: writes X30 = PC + 4, then jumps to address in X3. Used for virtual dispatch and function-pointer invocation.

JIT emits (x86_64)

mov  qword [rbp + x30_off], ; LR ← PC+4
     <next_guest_pc>
mov  rax, [rbp + x3_off]   ; new guest PC
ret                         ; exit to dispatcher

BLR always terminates the region (indirect target). Region linking happens lazily on first execution.

SVC #0 — supervisor call (syscall trampoline)

ARM64 source

SVC #0            ; 0xd4000001

Issues a Linux syscall. The syscall number is in X8; arguments in X0–X5. See Section 8 for the full path.

JIT emits (x86_64)

; SVC is interpreter-only
mov  rax, <svc_pc>        ; this guest PC
mov  rcx, <kInterpreted>
mov  [translation_cache + ...
     ], rcx                ; install marker
ret                        ; exit to dispatcher
; dispatcher then routes to
; interpreter, which handles
; the actual syscall.

SVC always terminates a region. The first time the JIT sees one, it installs kInterpreted at that PC so subsequent entries bypass the JIT.

MRS X0, DCZID_EL0 — read system register

ARM64 source

MRS X0, DCZID_EL0  ; 0xd53b0080

Reads an ARM system register into a GP register. DCZID_EL0 reports cache-line-zeroing capability and is queried by Bionic on startup. Many other system regs (TPIDR_EL0, MIDR, etc.) are also handled.

JIT emits (x86_64)

; per-register synthesized constant
; (DCZID_EL0 = 0x4 = block size 64B,
; DZP=0)
mov  qword [rbp + x0_off], 0x4

Most MRS reads compile to an immediate move — the “value” of the guest system register is synthesized by Berberis. DCZID_EL0 specifically was added in commit 039ecab2 after Bionic startup broke.

NOP — no operation

ARM64 source

NOP               ; 0xd503201f
                  ; alias of HINT #0

Useful for alignment padding and for the various HINT codes (YIELD = HINT #1, WFE = HINT #2, …) which are also encoded as NOP variants.

JIT emits (x86_64)

; nothing — emit no host bytes,
; advance guest PC by 4

Pure NOP costs nothing in the translation. WFE / YIELD on a x86 host are typically also no-ops (or pause) since the host's threading scheduler handles fairness.

DMB ISH — data memory barrier, inner-shareable

ARM64 source

DMB ISH           ; 0xd5033bbf

Full barrier ordering loads and stores. DMB ISHST is a store barrier; DMB ISHLD is a load barrier. DSB is stronger; ISB is instruction-cache.

JIT emits (x86_64)

mfence                    ; full barrier
; (or `lock or [rsp], 0`
; on CPUs without MFENCE)

x86 TSO covers most ordering for free, so even mfence is rarely needed for ordinary loads/stores. It's emitted for the “full fence” case to be safe. DMB ISHLD often collapses to nothing.

FADD D0, D1, D2 — floating-point add

ARM64 source

FADD D0, D1, D2   ; 0x1e622820

Double-precision FP add. ARM and x86 both use IEEE-754 with similar rounding modes — default round-to-nearest-even.

JIT emits (x86_64)

movsd  xmm0, [rbp + v1_off]
addsd  xmm0, [rbp + v2_off]
movsd  [rbp + v0_off], xmm0

Direct mapping. ARM's D registers map to the low 64 bits of the corresponding x86 XMM. Single-precision (S) uses movss/addss.

FMUL D0, D1, D2 — floating-point multiply

ARM64 source

FMUL D0, D1, D2   ; 0x1e620820

Double-precision FP multiply. Has regression tests under lite_translate_region_exec_tests.cc covering chained-multiply patterns — one of the spots historically hit by codegen bugs.

JIT emits (x86_64)

movsd  xmm0, [rbp + v1_off]
mulsd  xmm0, [rbp + v2_off]
movsd  [rbp + v0_off], xmm0

Same pattern as FADD with a different host opcode. FMADD (fused multiply-add) emits vfmadd* when FMA is available, otherwise mulsd + addsd with double rounding.

FCMP D0, D1 — floating-point compare

ARM64 source

FCMP D0, D1       ; 0x1e612000

Sets NZCV from comparing D0 and D1. Unordered (NaN) comparisons set C = V = 1 and clear N, Z.

JIT emits (x86_64)

movsd    xmm0, [rbp + v0_off]
ucomisd  xmm0, [rbp + v1_off]   ; sets RFLAGS
lahf
seto     al
and      ax, 0xc101
mov      [rbp + nzcv_off], ax

ucomisd sets ZF / PF / CF according to FP comparison, and NaNs set PF; the flag-pack step converts those into ARM's N / Z / C / V bits.

SCVTF D0, X0 — signed int to floating point

ARM64 source

SCVTF D0, X0      ; 0x9e620000

Convert signed 64-bit integer to double. UCVTF is the unsigned variant. SCVTF (scalar) is JIT-supported; some vector conversions fall back to the interpreter.

JIT emits (x86_64)

cvtsi2sd xmm0, qword [rbp + x0_off]
movsd    [rbp + v0_off], xmm0

Direct mapping to cvtsi2sd. The unsigned case needs a small fixup for values with bit 63 set (x86 has no cvtsi2sd for unsigned 64-bit before AVX-512).

FCVTZS X0, D0 — convert float to signed int (truncate)

ARM64 source

FCVTZS X0, D0     ; 0x9e780000

Convert double to int64 with round-toward-zero. ARM saturates on out-of-range; x86's cvttsd2si returns INT_MIN as a sentinel.

JIT emits (x86_64)

movsd     xmm0, [rbp + v0_off]
cvttsd2si rax, xmm0       ; truncate
mov       [rbp + x0_off], rax
; (+ saturating fixup branch for
; out-of-range to match ARM)

The saturation fix-up is one of the small fiddly details where ARM and x86 disagree at boundaries; a handful of conversions fall back to interpreter for that reason.

DUP V0.4S, W0 — broadcast scalar to vector

ARM64 source

DUP V0.4S, W0     ; 0x4e040c00

Replicates the 32-bit scalar W0 into all four lanes of V0. The element-from-vector form (DUP Vd.<T>, Vn.<T>[idx]) is also JIT-supported.

JIT emits (x86_64)

movd       xmm0, dword [rbp + x0_off]
pshufd     xmm0, xmm0, 0   ; broadcast lane 0
movdqa     [rbp + v0_off], xmm0

SSE2 pshufd with imm8 = 0 replicates the source's first lane to all four output lanes. With AVX2, a single vpbroadcastd does the whole thing.

ADD V0.4S, V1.4S, V2.4S — vector integer add

ARM64 source

ADD V0.4S, V1.4S, V2.4S  ; 0x4ea28420

Four-lane SIMD integer add. 16B / 8H / 4S / 2D arrangements give 128 bits of work per cycle on the host. Most basic SIMD arithmetic is JIT-supported.

JIT emits (x86_64)

movdqa  xmm0, [rbp + v1_off]
paddd   xmm0, [rbp + v2_off] ; packed 32-bit add
movdqa  [rbp + v0_off], xmm0

ARM ADD .4S = x86 paddd. Other widths map to paddb / paddw / paddq. Pairwise / widening / across-lanes versions fall back to the interpreter.

LD1 {V0.4S}, [X0] — vector load (one register)

ARM64 source

LD1 {V0.4S}, [X0]  ; 0x4c407800

Loads 128 bits from [X0] into V0. Multi-register forms (LD2, LD3, LD4 with de-interleaving) and per-element forms (LD1 {V0.S}[lane]) are interpreter-only because of the complex bit-decoding.

JIT emits (x86_64)

mov     rax, [rbp + x0_off]
movdqu  xmm0, [rax]
movdqa  [rbp + v0_off], xmm0

Unaligned movdqu because ARM LD1 doesn't require alignment. The interpreter path for multi-reg LDn handles the de-interleave with explicit shuffles.

4. Register Mapping

ARM64 exposes 31 general-purpose registers (X0–X30) plus SP and PC. x86_64 has 16. After reserving RAX for the guest PC, RBP for the ThreadState pointer, and RSP for the host stack, the JIT has 13 GP slots to pin guest registers into. Anything that doesn't fit lives in ThreadState memory and is spilled to/from a temp on demand.

x86_64 host pool (13 slots)

  • RBX
  • RSI
  • RDI
  • R8
  • R9
  • R10
  • R11
  • R12
  • R13
  • R14
  • R15
  • RDX *
  • RCX *

* RDX/RCX are reserved by specific x86 ops, so the allocator saves and restores them around DIV/MUL and variable shifts.

x86_64 reserved

  • RAX → guest PC
  • RBP → ThreadState *
  • RSP → host stack

ThreadState memory

  • X0…X30 (spilled)
  • SP
  • NZCV
  • V0…V31

When all 13 pool slots are taken and another guest register is needed, the allocator picks a temp, loads the guest value from ThreadState, uses it, and stores it back — rather than terminating the region. This keeps JIT regions long enough to amortize entry overhead.

5. Translation Lifecycle

What happens between an ARM64 byte sequence in memory and an x86_64 byte sequence the host CPU executes.

On region exit (a branch out, a syscall, register pressure, a JIT-unsupported opcode), control returns to the dispatcher with a new guest PC and the loop repeats.

6. Translation Cache Anatomy

The translation cache is the data structure that turns the runtime cost of binary translation from “every instruction” into “every region, once.” It is per-process, lives in writable + executable memory, and is keyed by guest PC.

Why region-based?

Per-instruction translation overhead is fatal. Region caching makes the marginal cost of a translated instruction approach the cost of an x86 instruction, plus the amortized cost of one translation.

What ends a region?

An out-of-region branch, a syscall, a call/return, exhausting the x86_64 register pool, or hitting an instruction the JIT can't handle. The region writes its exit pc back to RAX and rets to the dispatcher.

kInterpreted marker

A special cache value that means “don't try to JIT this PC again.” Crucial: the JIT must never install a real x86 entry for an interpreter-fallback PC, or you get an infinite loop of re-translation attempts.

7. NZCV Flag Emulation

ARM64 stores condition flags in NZCV (Negative, Zero, Carry, oVerflow). x86_64 stores them in RFLAGS with a different layout. Every flag-setting ARM64 op needs to leave behind something the next conditional can read in ARM's format.

For most flag-setting ops, the JIT emits the natural x86 instruction (which sets RFLAGS) and then captures the relevant bits into ARM's NZCV format using this pattern:

; after the flag-setting op (e.g. ADD, SUB, AND)
LAHF                  ; load SF, ZF, AF, PF, CF from RFLAGS into AH
SETO  AL              ; capture OF (overflow) into AL
AND   AX, <mask>      ; isolate N, Z, C, V bits
MOVW  [rbp+nzcv], AX  ; store packed NZCV into ThreadState

A subtle trap: PUSH/POP on x86_64 do not change RFLAGS, but SUB/ADD RSP, imm do. So when the JIT spills temporaries before LAHF, it has to use PUSH/POP or LEA — never SUB RSP — or the captured flags reflect the spill instead of the guest op.

8. Syscall Emulation Paths

Syscalls are always interpreter-only — they cross the kernel boundary and can have side effects the JIT can't reason about. When a guest issues SVC #0, the interpreter takes over, translates the call, runs the host syscall, and translates the result back.

futex

The guest stores its futex word at an ARM64-translated address; the host kernel reads it directly. Most cases are pass-through, but a few argument types (uaddr2, value bag) need bit-width-aware handling.

pthread_once / call_once

Naive forwarding of __cxa_guard_acquire through the proxy can deadlock when guest TLS doesn't agree with the host's view of who holds the once-flag. The kernel_api workaround short-circuits the guard for one-shot init.

mmap BSS zeroing

When an NDK 28+ APK's .so ends mid-page, the file-backed mmap leaves the page tail uninitialized. sys_mman_emulation.cc explicitly zeroes the tail so BSS appears as expected to the guest linker.

Why interpreter-only?

SVC can transfer control unpredictably (signals, exec). The JIT can't model post-syscall state safely, so the dispatcher always exits the region around a syscall.

9. Proxy Library Forwarding

If every guest API call had to be translated instruction-by-instruction down through the entire system library stack, performance would collapse. Digitalis intercepts well-known library boundaries and hands the call to the host implementation directly. Each proxy library is an ARM64 stub that marshals arguments and switches to the host x86_64 ABI.

There are 21 proxy libraries covering libc, libm, libvulkan, libEGL, libGLESv1_CM/v2/v3, libOpenSLES, libaaudio, libamidi, libandroid, libcamera2ndk, libmediandk, libbinder_ndk, libneuralnetworks, libjnigraphics, libnativewindow, and friends. The set of guest-to-proxy redirects is declared in system/etc/ld.config.arm64.txt.
